# Подключение analitikamed.ru к резервной странице

Репозиторий: https://github.com/f0cusNik/analitikamed-maintenance

Предпросмотр: https://f0cusnik.github.io/analitikamed-maintenance/

Публикация: Settings → Pages → Deploy from a branch → main → / (root).

## Подготовка без переключения основного сайта

1. В личных настройках GitHub откройте Settings → Pages → Add a domain и укажите analitikamed.ru.
2. GitHub покажет имя и значение TXT-записи для подтверждения домена. Добавьте её у действующего DNS-провайдера, нажмите Verify и сохраните TXT-запись постоянно. Подтверждение владения не выпускает HTTPS-сертификат.
3. Сохраните текущие A/AAAA-записи сайта и настройки www, если этот адрес используется. Узнайте действующие NS: регистрация домена в REG.RU не означает, что DNS обслуживает REG.RU.
4. Заранее установите TTL записей сайта 300 секунд, если провайдер позволяет. Старые кэши продолжат жить по предыдущему TTL.

## Плановая проверка или переключение при аварии

1. В настройках ЭТОГО репозитория Settings → Pages → Custom domain укажите analitikamed.ru и нажмите Save. Это меняет адрес Pages; служебный github.io адрес может начать перенаправлять на домен.
2. У действующего DNS-провайдера замените прежние A-записи корня (@) четырьмя записями:

   - 185.199.108.153
   - 185.199.109.153
   - 185.199.110.153
   - 185.199.111.153

3. Удалите либо замените направленные на прежний сервер AAAA-записи сайта. Иначе пользователи IPv6 могут продолжить попадать на основной сервер. Не добавляйте A GitHub рядом с A Beget как якобы автоматический резерв.
4. Если нужен www, настройте его CNAME на f0cusnik.github.io, предварительно сохранив прежнюю запись. Настройки почты (MX, почтовые TXT и связанные с почтой имена) не изменяйте.
5. Если в зоне уже используются CAA, проверьте, что они разрешают letsencrypt.org. Не добавляйте ограничительные CAA без проверки остальных сервисов.
6. Дождитесь успешной DNS-проверки и выпуска сертификата в Pages, включите Enforce HTTPS. GitHub указывает до часа на включение HTTPS после настройки домена; дополнительно учитывайте DNS-кэши. При зависшем выпуске проверьте DNS и CAA; после устранения причины может потребоваться удалить и повторно добавить Custom domain.
7. Проверьте https://analitikamed.ru/ и вложенный адрес /login, в том числе с мобильной сети. 404.html показывает ту же заглушку для неизвестных путей, но такие ответы сохраняют HTTP-статус 404. GitHub Pages не позволяет настроить собственный HTTP 503 для этой статической страницы.

## Возврат основного сайта

Восстановите сохранённые A/AAAA-записи и www. Учитывайте DNS-кэши. После возврата на Beget нельзя рассчитывать, что сертификат GitHub продолжит продлеваться. При следующей аварии его выпуск может потребоваться заново.

Если нужно сохранить независимый предпросмотр по github.io, удалите Custom domain в Pages после возврата DNS. Не удаляйте TXT подтверждения владения.

Ни подключение домена в Pages, ни изменение DNS не выполняются автоматически этим репозиторием. Пока Custom domain не задан, опубликован только предпросмотр github.io.

## Ограничения

- Это ручной резерв: автоматического контроля Beget и переключения DNS нет.
- Мгновенная готовность HTTPS после длительного ожидания не гарантируется. Загрузить собственный сертификат в GitHub Pages нельзя.
- Страница не использует внешние ресурсы, аналитику, cookies, формы или API Beget.
- robots.txt на проектном github.io URL лежит под путём проекта; запрет индексации каждой HTML-страницы обеспечивает meta robots. После подключения собственного домена robots.txt будет в корне.
